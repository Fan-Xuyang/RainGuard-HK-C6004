# v0.2.0 使用与验证

## 实际完成

- Node 服务新增 SQLite 共享记录，保存设施、人工复核工单和现场记录；重启保留。
- 每次上传检查共享版本。两个组员从同一版本开始修改，先上传者成功，后一位收到冲突；没有自动覆盖或自动合并。
- 操作日志记录版本、自行填写的操作人、时间及记录数量。共享口令仅在当前页面输入，不写入浏览器持久存储。
- 助手/知识库接入九份官方资料。网页说明保留完整短文，PDF 按物理页抽取并分块。检索采用词频/长度归一化与文档证据配额，减少长 PDF 占满检索结果的情况。
- 历史模型页展示三站、两种微量雨策略、五种方法的 30 组真实实验。提供固定时间划分、来源哈希、混淆矩阵和环境版本下载。

## 启动与共享

需要 Node 22.13+（内置 SQLite 在该版本仍为实验接口，程序启动会有提示）。推荐使用项目已测试的 Node 24。

```bash
npm ci
npm start
```

打开 http://localhost:8095。天气及知识检索不需要模型密钥。

一台运行服务的组内机器在 `.env.local` 配置随机 `WORKSPACE_TOKEN`，至少 24 字符。可用 `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"` 在自己的终端生成，再自行复制到本机配置；不要提交或截图公开。若只做本机两浏览器演示，保持 `HOST=127.0.0.1`。受信任局域网多人连接需要 `HOST=0.0.0.0` 并正确配置系统网络访问。

进入“设施与复核”：

1. 输入共享口令及操作人，连接查看版本。已有共享记录时需先载入，不能直接拿旧本机视图覆盖。
2. 点击“备份并载入共享记录”。会下载当前本机记录 JSON，然后载入共享设施、工单及现场记录。
3. 完成真实登记/人工复核，点击“上传本机记录”。同组成员再次载入即可看到保存结果。
4. 若出现冲突，先保留本机备份，再载入其他组员的版本，整理变更后上传。没有后台自动同步，不上传的编辑仍仅在本机。

私人对话、自导入知识和浏览期间趋势不上传。附件作为记录的一部分共享；记录总量限制为 4 MB。仅提交已获授权的现场资料。数据库默认 `runtime/workspace.sqlite`，在 Git 中忽略。操作人是自行填报，不代表独立身份认证；本版本没有每人账户/角色系统。

## 实验与知识复现

```bash
python -m pip install -r requirements.txt
python scripts/download_dataset.py
npm run knowledge:sync
npm run experiment
npm test
npm run build
```

已有数据包时跳过下载。知识同步核验原 HTML/PDF 的 SHA-256，再将正文接入网站；17 MB 的原 PDF 保留在完整数据包，避免全部打入 Worker。网页库当前 139 个检索片段，不同于完整数据包的 58 个按全文滑窗片段。

实验报告见 `docs/EXPERIMENTS.md`。源文件哈希、版本和参数见 `hk-web/data/experiments.json`。没有使用测试集挑参数；两个微量雨策略可用日期不同，不能据此推断处理策略的因果效果。随机森林未在所有指标/站点胜过简单模型。

## 验证范围和运行边界

自动检查涵盖共享鉴权、跨站拒绝、无效结构、大小限制、并发冲突、数据库重新打开后持久保存、审计，及知识来源、检索阈值、助手错误处理和页面流程。模型实验在真实数据包上实际执行。

本轮更新的是 GitHub 协作版本，没有部署新的共享生产服务。原 Sites 演示不因 GitHub 推送自动更新。Worker/Sites 构建可以运行天气及助手；SQLite 共享接口只在 Node 服务中实现，尚未迁移到 D1。互联网上使用需配置 HTTPS 与适合实际成员的身份管理。历史日雨量仍存在月度发布滞后，不能将回测输出视为实时日预测。
